# monorm.inherit

Shares model shape between models and lets one model replace another.
It adds the attributes `@@inherit.abstract`, `@@inherit.extends` and `@@inherit.override`.

## Install

Nothing to install.
The extension ships inside the one `monorm` wheel (Python module `monorm_inherit`) and the one `monorm` npm package (`monorm/extensions/inherit`).
The Rust crate is `monorm-inherit` (`publish = false`; the host builds it into the wheel and the addon).

## Smallest example

```prisma
datasource db {
  provider = "sqlite"
}

model Timestamped {
  created_at DateTime @default(now())
  @@inherit.abstract
}

model Note {
  id    Int    @id @default(autoincrement())
  title String
  @@inherit.extends("Timestamped")
}
```

```python
import monorm

models = monorm.loads(schema_text)
await db.create_tables()
note = await models["Note"].objects.using(db).insert(title="first")
print(note.created_at)  # set by the default of the abstract model
```

```ts
import { loads } from "monorm";

const { Note } = loads(schemaText);
await db.createTables();
const note = await Note.objects.using(db).insert({ title: "first" });
console.log(note.createdAt);
```

`db` comes from `monorm.connect(url)` (Python) and `connect(url)` (TypeScript).
`Timestamped` has no table.
`Note` has the table `note` with the columns `id`, `title` and `created_at`.

## How it works

**Pass.** `monorm.inherit.expand` runs in the `expansion` phase, before the host and the other extensions see the schema.
Its effects are `models.inherit` and `storage.inherit`.
After the pass the schema has ordinary models only, so the rest of the engine knows nothing about inheritance.

**What the pass does.**

- An abstract model is removed. Each child gets a copy of its fields, relations, indexes, constraints, `@@query_set` and `@@model_methods`.
- A relation name with `{model}` is expanded for each child (`Role.user_roles` for `User`).
- A list relation with `through: "{model}Team"` gets one generated join model for each child.
- An override copies the base model, takes its table, and makes the relations of the base point to the override.

**What the pass checks.**
It refuses `@@map`, `@@renamed_from` and `@@partition` on an abstract model, a relation to an abstract model, a field or a class that two bases declare, `{model}` in a concrete model, two overrides of one model, a changed primary key type in an override, and a composite key on a join model.
The user doc lists each message.

**SQL.** The pass adds no SQL of its own.
It adds ordinary tables, columns and foreign keys, which the host migrates.
A generated join model gives this table on PostgreSQL (`sqlmigrate`):

```sql
CREATE TABLE "auth_user_teams" (
    "id" integer GENERATED BY DEFAULT AS IDENTITY NOT NULL,
    "user_id" integer NOT NULL,
    "team_id" integer NOT NULL,
    CONSTRAINT "auth_user_teams_pkey" PRIMARY KEY ("id"),
    CONSTRAINT "auth_user_teams_user_id_team_id_key" UNIQUE ("user_id", "team_id"),
    CONSTRAINT "auth_user_teams_user_id_fkey" FOREIGN KEY ("user_id") REFERENCES "auth_user" ("id") ON DELETE CASCADE,
    CONSTRAINT "auth_user_teams_team_id_fkey" FOREIGN KEY ("team_id") REFERENCES "team" ("id") ON DELETE CASCADE
);
```

**Runtime.** The extension has no runtime hook.
The query set and the instance class have no members.
The only runtime API is `model_for(name, registry=None)` (Python) and `modelFor(name, registry)` (TypeScript).
It returns the model that overrides `name`, or `name` itself.
It reads the value `model_overrides` that the pass writes into the behavior section of the schema.

**Rust and bindings.** All logic is in the Rust crate (`src/lib.rs`).
The Python and TypeScript code is only `model_for` and `modelFor`.

**Other extensions.** The pass runs first.
Attributes that other extensions add to an abstract model, such as `@@history.track`, are copied to each child before those extensions run.
Code generation (`crates/core`) writes the types of abstract models (`AbstractUserFields` in Python, `AbstractUserData` in TypeScript).

## Layout

```
extensions/inherit/
  Cargo.toml                 crate monorm-inherit
  monorm-extension.toml      manifest: one pass, three attributes
  src/lib.rs                 the pass
  python/monorm_inherit/     model_for
  typescript/src/index.ts    modelFor
  tests/lowering.rs          pass tests
  tests/migration.rs         migration tests
  tests/fixtures/schema.prisma
  tests/public/python.py     end-to-end, SQLite
  tests/public/node.mjs      end-to-end, SQLite
```

The type tests are in `crates/core/tests/abstract_typing.rs`.

```bash
cargo test -q -p monorm-inherit
python languages/python/packaging/stage.py && maturin develop   # the public tests need the built wheel
python extensions/inherit/tests/public/python.py
(cd languages/js && npm run assemble && node ../../extensions/inherit/tests/public/node.mjs)
```

## Limits

- An abstract model has no runtime class, and its generated types carry fields only, not relations.
- A join model has no extra fields. Write the join model by hand for extra fields.
- An override cannot change the type of the primary key of the base model.
- `monorm pull` writes ordinary models and no `@@inherit.*` attribute.
- A schema error starts with `extension monorm.inherit: pass monorm.inherit.expand:`.
